## Issues found and fixed

- Marketplace creator queries originally had two possible version
  relationships. The route now selects the listing-history relationship
  explicitly, preventing ambiguous PostgREST joins.
- Cryptographic extension functions inside hardened, empty-search-path
  functions are now schema-qualified.
- Legacy counters could drift across month boundaries. The new monthly ledger
  is authoritative and the scheduler synchronizes only changed legacy rows.
- Metering previously happened after successful persistence, which could miss
  failed but billable model responses. Usage is now recorded immediately after
  every engine response with deterministic idempotency keys.
- Marketplace installs previously cloned directly from mutable templates. New
  listings install only from immutable, hashed versions and always create
  drafts.

## Blockers and constraints

- Payments are intentionally not connected. Plans are billing-ready and include
  external customer/subscription fields, but upgrades use a no-cost request
  workflow until a payment provider and budget are approved.
- The frontend reports a non-blocking large-bundle warning; route-level code
  splitting is a future performance task.
- The dependency audit reports a high React Router advisory limited to unstable
  server/RSC mode. AgentForge is a client-only BrowserRouter application and
  does not use that path; a forced breaking downgrade was not introduced.
- Render's free instance can sleep and may delay the first request while waking.
