# Days 16-17 Report - Organization Workspaces and Governance

Date: 2026-07-29

## Audited

- Inspected authentication, ownership boundaries, agents, workflows, chains,
  knowledge bases, evaluations, multi-agent systems, durable jobs, usage
  controls, Supabase security, the Render API, and the Vercel application
  before implementation.
- Preserved all existing users, resources, executions, credentials, usage
  history, marketplace data, and production configuration.
- Kept the release cost-free: verification made no model calls, purchased no
  service, and used the existing free infrastructure.

  migration helper was removed immediately afterward.

## Day 16 built - organization workspaces

- Added isolated organization workspaces with stable slugs, descriptions,
  lifecycle status, and plan-aware organization and member limits.
- Added owner, admin, builder, and viewer roles with a centralized role
  hierarchy enforced by the backend.
- Added expiring, one-time invitation links stored only as cryptographic hashes.
  Acceptance is restricted to the email address in the authenticated JWT.
- Added member-role management with protection for the final owner.
- Added controlled sharing for agents, workflows, chains, knowledge bases,
  evaluations, and multi-agent systems.
- Added explicit view, run, and edit access levels for shared resources.
- Added safe cloning for shared agents and workflows. Clones are user-owned
  drafts and never silently replace or activate an existing resource.
- Protected shared resources from deletion until they are deliberately
  unshared, preventing broken organization references.
- Added workspace archive, restore, and strongly confirmed deletion. Permanent
  deletion requires owner access, archived state, and the exact organization
  slug.
- Added a complete Organizations interface for workspace creation, selection,
  members, invitations, roles, shared assets, cloning, and lifecycle controls.

## Day 17 built - governance and compliance

- Added organization execution policies covering permitted models, maximum
  calls, maximum estimated cost, approval mode, minimum approvers, audit
  retention, and export availability.
- Enforced organization policy before model execution across direct agents,
  workflows, chains, evaluations, and multi-agent runs.
- Added governance change requests with independent approval, rejection,
  cancellation, expiration, and recorded decisions.
- Added database-level protection against self-approval and conflicting second
  decisions.
- Added immutable, append-only organization audit events with strictly ordered
  sequence numbers and SHA-256 hash chaining.
- Added recursive sensitive-data redaction and HMAC-protected request context;
  raw IP addresses are never stored.
- Added audit filters for actor, action, target, and date.
- Added verifiable JSON and CSV compliance exports with SHA-256 digests and an
  immutable export ledger.
- Added retention checkpoints while preserving immutable audit records by
  default.
- Added scheduled cleanup for expired invitations, governance requests, and
  eligible retention data.
- Added governance policy editing, approval queues, audit search, export
  verification notices, and archive/restore controls to the Organizations UI.
- Split protected frontend routes into lazy-loaded chunks. The main production
  bundle is now 463.44 KB instead of exceeding the 500 KB warning threshold.

## Issues found and fixed

- Supabase safe-update mode rejected an initially unbounded migration update.
  The helper transaction rolled back completely; the statement was constrained
  with an explicit predicate, then both migrations applied successfully.
- Governance decisions originally needed stronger database-level independence
  guarantees. Triggers now reject self-approval and contradictory decisions,
  even if a future API route is implemented incorrectly.
- Shared assets could previously be deleted by their personal owner while still
  referenced by an organization. Every supported deletion route now requires
  explicit unsharing first.
- Expired invitations and membership limits had edge cases during concurrent
  lifecycle changes. Limits and expiry are now checked inside the authoritative
  service/database path.
- The frontend's single protected bundle exceeded the build warning threshold.
  Route-level lazy loading reduced the main bundle to 463.44 KB and moved the
  Organizations interface into a 27.26 KB route chunk.

## Blockers and constraints

- Invitation delivery is currently provider-neutral and cost-free: the secure
  invitation link is shown once for the owner to copy. Automatic email delivery
  needs a connected email provider.
- Enterprise SSO, SCIM provisioning, and verified-domain enforcement are not
  included yet.
- The frontend dependency audit still reports a high React Router advisory
  limited to unstable server/RSC mode. AgentForge uses client-side
  `BrowserRouter` and does not use the affected path; a breaking forced
  downgrade was not introduced.
- Render's free instance can sleep and may delay the first request while waking.
