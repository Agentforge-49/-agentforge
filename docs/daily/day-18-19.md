## Day 18 built - enterprise identity and access

- Added globally unique organization domains with normalized hostnames,
  one-time DNS TXT challenges, SHA-256 token storage, verification attempts,
  and verified timestamps.
- Added SSO-ready OIDC and SAML configuration with provider name, issuer,
  metadata URL, client ID, JIT provisioning, and a restricted default role.
- Added a verified-domain gate before SSO enforcement can be enabled.
- Added MFA, maximum-session, and idle-timeout policy with bounded values and
  cross-field validation.
- Added SCIM 2.0-style user listing, provisioning, updating, reactivation, and
  deprovisioning endpoints.
- SCIM bearer credentials are generated from cryptographic randomness, stored
  only as SHA-256 hashes, shown once, independently rotatable, and fail closed
  when disabled.
- SCIM can assign only viewer or builder access intent; directory systems
  cannot provision admin or owner roles.
- SCIM email addresses must belong to a DNS-verified organization domain.
- Added directory identity records with external IDs, version metadata,
  requested role, linked-user support, bounded attributes, and sync history.
- Added access-review snapshots covering every active member.
- Added retain, role-change, and revoke decisions with reviewer attribution,
  notes, automatic completion, and organization audit events.
- Reviewers cannot change or revoke their own access, and owner access cannot
  be changed through an access review.
- Access-review decisions and membership enforcement now commit in one
  database transaction.
- Added the Enterprise Access page with workspace selection, domain
  challenges, SSO/session controls, one-time SCIM tokens, directory status,
  access-review creation, and member decisions.

## Day 19 built - provider-neutral billing readiness

- Added billing customer profiles separated from authentication profiles.
- Added provider-neutral checkout sessions, subscriptions, invoices, webhook
  events, and a billing ledger.
- Added monthly and annual checkout contracts for Pro and Enterprise without
  inventing or charging an unapproved price.
- Checkout tokens are cryptographically random, stored only as SHA-256 hashes,
  expire after 30 minutes, and are accepted only once.
- Added a complete billing sandbox lifecycle: checkout creation, completion,
  simulated invoice, current subscription, scheduled cancellation, resume,
  immediate cancellation, and automatic expiration.
- Sandbox completion is structurally separated from production entitlements:
  it cannot grant plan access, increase limits, or charge money.
- Added a provider-neutral live webhook boundary with HMAC signature
  verification, payload hashing, provider/event idempotency, and fail-closed
  configuration.
- Live webhooks remain unavailable unless billing live mode, a provider, and a
  webhook secret are explicitly configured.
- Added a strictly ordered, SHA-256 hash-chained, append-only billing ledger.
- Added a service-only sandbox purge that refuses to run if any live billing
  record exists. This supports safe test cleanup and account deletion without
  weakening live ledger protection.
- Added scheduled expiration for abandoned checkout sessions and ended sandbox
  subscriptions.
- Added the Billing page with an explicit sandbox banner, real entitlement,
  isolated test subscription, checkout simulations, billing profile, invoices,
  cancellation controls, and the immutable ledger.

## Issues found and fixed

- The SQL editor retained draft content when text was initially replaced,
  causing a duplicate-table error. The transaction failed safely. The editor
  was cleared, the migration was applied once, and schema assertions confirmed
  all expected objects and no partial state.
- The first end-to-end cleanup found that an append-only billing trigger also
  blocked deletion of a temporary sandbox user. A service-only purge now
  permits deletion only when every billing record is test mode and rejects any
  user with live billing data.
- Access-review membership changes initially followed the decision RPC as a
  separate API update. Enforcement was moved into the database function so the
  decision, role change or revocation, and review completion are atomic.
- SSO enforcement could otherwise be enabled without proving domain ownership.
  The route now requires at least one verified organization domain.
- Sandbox checkout could have been confused with a real plan upgrade. The
  response, database mode, UI, invoice status, ledger details, and entitlement
  assertions now all state and enforce that no real access or charge occurs.

## Blockers and constraints

- Native OIDC/SAML login is not activated. Configuration and enforcement gates
  are ready, but a provider application and securely stored provider secret are
  required before real SSO authentication can be enabled.
- SCIM manages the organization directory lifecycle but does not silently
  create a Supabase login account or send email. Users still join through the
  controlled invitation flow.
- Real DNS success was not attempted against a domain the user does not own.
  Exact DNS challenge matching has unit coverage; production verified the
  hashed challenge, invalid-token rejection, domain gate, and post-verification
  lifecycle using temporary service-role test setup.
- No live payment provider, checkout, price, or webhook secret is configured.
  The billing system therefore remains safely in test mode.
- The frontend dependency audit still reports a high React Router advisory
  limited to unstable server/RSC mode. AgentForge uses client-side
  `BrowserRouter` and does not use the affected path.
- Render's free instance can sleep and may delay the first request while waking.
