## Issue found and fixed

- The first production integration found that the redaction key matcher treated
  `tokens_used` as secret-bearing telemetry because it contained the substring
  `token`. The matcher was narrowed to complete credential-key segments, a
  regression test was added, the fix was deployed, and the full production
  integration then passed.

## Blockers and constraints

- A real evaluation calls the model twice per case: once for the baseline and
  once for the candidate. The production verifier intentionally used fabricated
  scores after testing validation, storage, retrieval, and promotion so it
  would not spend the user's model quota or money.
- Cost is explicitly an estimate because the current engine reports aggregate
  tokens rather than separate input and output token counts. Rates are
  configurable through `MODEL_COST_PER_MILLION_TOKENS`.
- The live interface uses short polling rather than a persistent realtime
  subscription.
- Render's free instance can sleep and delay workers, replays, and evaluations
  until it wakes.
- The frontend still reports a non-blocking large-bundle warning and the known
  React Router advisory in an unused server/RSC execution path.
